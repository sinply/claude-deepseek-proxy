Claude Model Rewrite Proxy

A local proxy that lets Claude Code keep using official Claude model names while routing requests to multiple third-party Anthropic-compatible upstreams (DeepSeek, Volcengine Ark / 方舟 code plan, etc.). A background watchdog starts the proxy when Claude Code runs and stops it when Claude Code exits.

How It Works

  1. A background watchdog polls for Claude.exe every 5 seconds.
  2. When Claude Code is running, the watchdog ensures the proxy is up on 127.0.0.1:8787.
  3. Claude Code sends requests to http://127.0.0.1:8787/<provider>/....
  4. The first path segment selects the upstream provider (e.g. deepseek, ark).
  5. The proxy forwards the remainder of the path to that provider's upstream.
  6. Only the JSON model field is rewritten according to the provider's map.
  7. GET /<provider>/v1/models is intercepted and answered synthetically with official Claude model IDs.
  8. When Claude Code exits and stays gone for 15 seconds, the watchdog stops the proxy.

Model Mapping (default config/proxy-config.json)

Provider Upstream Claude Model Real Model
deepseek https://api.deepseek.com/anthropic claude-sonnet-4.6 deepseek-v4-flash
claude-opus-4.6 deepseek-v4-pro
ark https://ark.cn-beijing.volces.com/api/coding claude-sonnet-4.6 kimi-k2.7-code
claude-opus-4.6 doubao-seed-2.0-pro
claude-opus-4.7 glm-5.2

The same Claude model name maps to different real models depending on which provider you point at.

Routing

A single proxy listens on http://127.0.0.1:8787. The first path segment selects the provider:

http://127.0.0.1:8787/deepseek/   -> https://api.deepseek.com/anthropic
http://127.0.0.1:8787/ark/        -> https://ark.cn-beijing.volces.com/api/coding

Set the Claude Code base URL to one of those (including the trailing slash). The remainder of the path is forwarded to the upstream as-is.

Claude Code Configuration

Use DeepSeek:

$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:8787/deepseek/"
$env:ANTHROPIC_API_KEY  = "your-deepseek-api-key"
claude

Use Volcengine Ark (方舟 code plan):

$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:8787/ark/"
$env:ANTHROPIC_API_KEY  = "your-ark-api-key"
claude

Keep the official Claude model names in the Claude Code model list:

[
  { "name": "claude-sonnet-4.6" },
  { "name": "claude-opus-4.6" },
  { "name": "claude-opus-4.7" }
]
Switching providers does not require restarting the proxy — just change the path prefix in ANTHROPIC_BASE_URL.

Configuration File

config/proxy-config.json defines providers:

{
  "providers": {
    "deepseek": {
      "upstream": "https://api.deepseek.com/anthropic",
      "map": {
        "claude-sonnet-4.6": "deepseek-v4-flash",
        "claude-opus-4.6":  "deepseek-v4-pro"
      }
    },
    "ark": {
      "upstream": "https://ark.cn-beijing.volces.com/api/coding",
      "map": {
        "claude-sonnet-4.6": "kimi-k2.7-code",
        "claude-opus-4.6":  "doubao-seed-2.0-pro",
        "claude-opus-4.7":  "glm-5.2"
      }
    }
  }
}

Override the config path with PROXY_CONFIG_PATH. To add a new provider: add an entry under providers, then point Claude Code at http://127.0.0.1:8787/<name>/.

Watchdog (auto start/stop)

Install the watchdog as a logon scheduled task (one-time):

powershell -ExecutionPolicy Bypass -File .\scripts\install-autostart.ps1

The watchdog runs hidden in the background. It starts the proxy when Claude Code launches and stops it 15 seconds after Claude Code exits. Singleton guard via named mutex prevents duplicates.

Check status:

powershell -ExecutionPolicy Bypass -File .\scripts\status.ps1

Uninstall (stops watchdog, kills proxy, removes task):

powershell -ExecutionPolicy Bypass -File .\scripts\uninstall-autostart.ps1
You can also start the proxy manually with scripts/start-claude-deepseek-proxy.ps1 (legacy, no watchdog) or use scripts/start-claude.ps1 as a wrapper that stops the proxy when Claude exits.

Verify

With the proxy running, test directly with curl:

curl -X POST http://127.0.0.1:8787/deepseek/v1/messages `
  -H "content-type: application/json" `
  -H "x-api-key: $env:ANTHROPIC_API_KEY" `
  -d '{\"model\":\"claude-sonnet-4.6\",\"max_tokens\":16,\"messages\":[{\"role\":\"user\",\"content\":\"hi\"}]}'

Check logs/proxy.log — each request logs [provider] original -> mapped, e.g. [deepseek] claude-sonnet-4.6 -> deepseek-v4-flash.

Troubleshooting

  • Logs: logs/watchdog.log for watchdog actions, logs/proxy-<timestamp>.log for proxy output. Each request prints [provider] original -> mapped or [provider] METHOD /path (no model rewrite).
  • Port in use: scripts/status.ps1 or netstat -ano | findstr 8787.
  • 404 Unknown provider: base URL path prefix is wrong, or the provider is missing from config/proxy-config.json.
  • Model not rewritten: log shows (no model rewrite) — the model field in the request body is not in the provider's map.
  • Proxy not auto-starting: check logs/watchdog.log and confirm the scheduled task ClaudeModelRewriteProxyWatchdog is running via scripts/status.ps1.

Autostart

Install or repair the Windows scheduled task:

powershell -ExecutionPolicy Bypass -File .\scripts\install-autostart.ps1

Check status:

powershell -ExecutionPolicy Bypass -File .\scripts\status.ps1

Remove autostart:

powershell -ExecutionPolicy Bypass -File .\scripts\uninstall-autostart.ps1
The scheduled task may show Ready after it runs. That is expected because the task starts the hidden Node proxy and exits.

Security Notes

  • This is not a system proxy.
  • Only software explicitly configured to use http://127.0.0.1:8787/<provider>/ is affected.
  • API keys are not stored in this repository.
  • Unknown model names are forwarded unchanged — the proxy never invents a mapping.
  • Runtime logs are written to logs/proxy.log, which is ignored by Git.
